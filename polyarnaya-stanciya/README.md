# 🌌 Полярная станция — миссия 2027

**Браузерный кооперативный квест для курса «Искусственный интеллект», 1–4 классы.**

В игре участвуют **2–10 детей** и отдельно **ведущий/преподаватель**. Учитель создаёт комнату, отправляет **одну ссылку**, дети заходят со своих телефонов, планшетов или компьютеров и выбирают **неповторяющиеся роли**. Все события синхронизируются между устройствами в реальном времени.


## Публикация именно из этого репозитория

Исходники находятся в папке `polyarnaya-stanciya` репозитория `MaretDangaeva/ai`. На Render при создании Web Service укажите **Root Directory:** `polyarnaya-stanciya`, **Build Command:** `npm install`, **Start Command:** `npm start`, **Health Check Path:** `/api/health`. GitHub Pages не запускает Node.js и не подходит для совместной игры.

## Четыре миссии

1. **📡 Радиомаяк.** Каждый видит только свой секретный номер. Нужно договориться и по очереди отправить личный сигнал. Нажали не по порядку — попытка начинается снова.
2. **🎁 Учебный конвейер.** Каждый получает собственные коробки с отличающимися цветами и знаками. Все вместе размечают примеры для ИИ, запускают проверку, при ошибках исправляют маркировку. Это игровая **симуляция обучения ИИ**, без подключения настоящей модели.
3. **🤖 Ледяной маршрут.** Вся команда видит одну карту. Стрелки управления распределены между детьми. Нужно зарядить личные модули, собрать три искры и довести робота до портала.
4. **🌌 Зажги сияние.** Ведущий запускает 25 секунд. Все участники должны вовремя нажать личную кнопку. Только тогда команда побеждает.

## Роли (10 вариантов)

Радиотехник, Навигатор, Инженер, Тренер ИИ, Детектив, Художник, Пилот, Защитник, Связист и Хранитель энергии. **Один ребёнок — одна роль; роль нельзя занять дважды.** Название роли задаёт образ персонажа, а личные игровые задачи выдаются на станциях: свой фрагмент сигнала, свои посылки, свои команды робота и свой заряд в финале.

## Самая важная особенность публикации

> ⚠️ **GitHub Pages не подходит для живой многопользовательской версии**, потому что не запускает сервер Node.js. GitHub нужен как хранилище исходников, а размещать игру следует на серверном хостинге, например [Render](https://render.com/) или Railway. В репозитории уже есть `render.yaml`.

### Как выложить игру и получить одну рабочую ссылку

1. Создайте **новый репозиторий GitHub**.
2. Распакуйте ZIP и загрузите **все файлы из папки проекта** (чтобы `server.js`, `package.json` и `render.yaml` лежали в корне репозитория).
3. Зайдите на [Render](https://dashboard.render.com/), авторизуйтесь и выберите **New → Web Service**.
4. Подключите GitHub, выберите репозиторий и создайте сервис. При необходимости укажите:
   - **Language / Runtime:** Node
   - **Build command:** `npm install`
   - **Start command:** `npm start`
   - **Health check path:** `/api/health`
   - **Instance type / Plan:** доступный вам план (например, Free, если он доступен).
5. Получите HTTPS-адрес вида `https://имя-приложения.onrender.com`. **Это стартовый адрес для ведущего**. Он нажимает «Создать комнату» и **копирует появившуюся ссылку комнаты** — именно её отправляет всей группе.
6. Ученики открывают ссылку комнаты, вводят псевдонимы и выбирают свободные роли. Когда готовы от 2 до 10 детей, ведущий нажимает «Начать миссию».

Ссылка на комнату содержит код, например `https://адрес-приложения/?room=ABC23`. Каждый участник получает свой приватный пульт на **одной и той же ссылке**.

### Для проверки на своём компьютере

Установите [Node.js](https://nodejs.org/) 18+ и в папке проекта выполните:

```bash
npm start
```

Откройте `http://localhost:3000` и создайте комнату. Для тестирования разных ролей можно открыть ссылку в разных браузерах или в обычном окне и режиме инкогнито. Локальный адрес `localhost` работает только на компьютере, где запущен сервер, и не подходит как внешняя ссылка для детей.

Проверка сервера и игровых механик:

```bash
npm test
```

**В игре нет платных API, внешних JS-библиотек или зависимости от настоящих нейросетей.** Node.js использует стандартные возможности HTTP и Server-Sent Events (SSE); изменения сразу приходят всем подключённым экранам.

## Для преподавателя

- **Возраст:** 1–4 классы, особенно 2–4; детям 1 класса можно читать задания вслух.
- **Продолжительность:** ориентировочно 20–30 минут всей группой; ведущий может пропустить этап.
- **Состав:** 2–10 участников + ведущий (не занимает роль).
- **Сюжет:** полярный ИИ сломался, а дети восстанавливают связь, данные, маршрут и энергию.
- **Навыки:** общение, распределение ролей, правила для ИИ, разметка данных, алгоритмы движения, проверка ошибок и кооперация.
- **Рекомендация:** ведущий демонстрирует свой экран и помогает детям общаться голосом через урок. Встроенный чат отсутствует: дети не отправляют сообщения друг другу внутри игры.
- **Если кто-то потерял соединение:** нужно открыть ту же страницу на том же устройстве/вкладке. Пульт восстановится из `sessionStorage`. Если ребёнок вышел окончательно, ведущий может начать игру заново и при необходимости освободить роль.

## Ограничения

- Состояние комнат хранится **только в оперативной памяти сервера**. Перезапуск или переход сервиса в спящий режим удаляет комнаты и ход игры. Некоторые бесплатные хостинги могут усыплять приложение после простоя; перед уроком лучше открыть игру и проверить, что всё работает.
- Комната автоматически удаляется после 4 часов без изменений. Этот прототип рассчитан на один серверный процесс, **без горизонтального масштабирования**.
- Для командной игры всем нужен доступ к интернету и сайт, на котором размещён Node-сервер.
- Имена участников нужны только для отображения команды; вводите **игровые псевдонимы**, а не персональные данные.
- Финальный отсчёт требует, чтобы все оставшиеся в составе участники нажали свои кнопки. Ведущий может повторить попытку.

```text

├── public/
```
